# 文档审计方法与纠错记录

> 2026-10-14 ｜ 对象：本仓库全部 204 个 markdown
> 目的：让"数量 / 比例 / 覆盖率"类结论**可追溯到口径**，而不是凭印象写。

---

## 为什么要做这次审计

框架类项目最大的风险不是代码错，而是**文档互相矛盾**——同一个数字在不同文件里不一样，读者不知道该信哪个。

本仓库在审计前就存在这类问题，且是自证的：一份健康审计报告在**同一节里**既写"56 项问题"，又写"35 高 + 38 中 + 23 低"。

所以先建对账基准，再谈结论。

---

## 方法：先自举，再分片，禁止估数

### 1. 建索引（唯一对账基准）

递归收集 `*.md`（跳过 `node_modules` / `.npm-cache` / `.git` / `__pycache__`），每个文件记录：

`path · h1 · lines · bytes · mtime · tracked · ref_count · shard`

- `tracked`：与 `git ls-files` 求交
- `ref_count`：以文件名主干在**其它** md 正文中出现的次数计（跨文件重要度）
- `shard`：按目录前缀规则判定

**纪律：任何数量结论都必须写明来源是这份索引的哪个聚合口径。**

### 2. 分片取证（8 片，深度分级）

| 深度 | 含义 |
|---|---|
| D2 | 逐条事实，表格化，每条带 `路径:行号` |
| D1 | 摘要级事实，只记关键结论 + 证据路径 |
| D0 | 仅建档（路径 / H1 / 行数 / 字节 / 状态），**不读正文** |

永久归档区采用 D0：只建档、不复读正文。这条约定后来写进了 `docs/ARCHIVE.md`。

### 3. 汇总（按序五个动作）

1. **对账**：各片文件数 + 缺失清单 = 索引总数（等式必须闭合）
2. **交叉一致性**：同一实体（数字/日期/编号）在多片出现必须取值一致
3. **引用闭环**：A 片声称引用片外 X，则 X 所属片必须有对称记录
4. **基线裁决**：对预先交底的"已知事实"逐条独立复核
5. **叙事匹配**：把预期叙事逐条映射到证据，**无法映射的标【无证据支撑】**

第 5 条是防"自说自话"的最后一道闸门。

### 4. 隔离纪律（关键）

取证执行时遵守三条硬约束：

- **叙事隔离**：取证者不得提前知道项目的"预期故事"，否则会去找支持该故事的证据（确认偏误）。叙事只在汇总层注入。
- **单向通信**：取证者之间不通信，只产出结构化结果，防止幻觉传染。
- **职责不对称**：取证者只记录事实，**不做解释**；解释权归汇总层。
  （同一模型下能力无差异，只能靠**信息可见性**制造不对称。）

## 审计结果（节选）

| 项 | 结果 |
|---|---|
| 索引口径文件数 | 204（逐片实测与预期表**零差额**） |
| 对账等式 | `Σ各片 + 缺失清单 = 204` **闭合** |
| 失效相对链接 | **186 处**（涉及 34 个文件）→ 已全部修复至 **0** |
| 已验证链接 | 861 个相对链接全部可解析 |

**186 处失效链接的归因**（机械统计，非估计）：

| 原因 | 处数 |
|---|---|
| 子目录少一层 `../` | 132（`plugin/` 73 + `investigation/` 43 + `adr/` 16） |
| 裸文件名（同目录不存在） | 28 |
| 其它路径错误 | 21 |
| `./` 前缀解析错误 | 5 |

链接修复采用**保守策略**：仅在目标文件名唯一、或尾部路径段匹配唯一时才自动修改；有歧义的一律人工判定。指向**已按设计删除**的文件的链接，改为纯文本并加注，而不是改指别处。

## 纠错记录（审计自身的错误）

审计结论本身也经过一轮整改复核，**5 条被证伪**，全部保留在案：

| 原结论 | 实测 |
|---|---|
| 失效引用仅 11 项 | 实为 **186 处**（原估只覆盖了被点名的少数几处） |
| 某构建目录有 4 个文件被 git 跟踪 | **误报**，该目录本就未被跟踪 |
| 全库 `D-*` 决策应为 10 个 | 实为 **13 个**（漏算了归档目录中的 3 个） |
| 某 ADR 的相对路径解析可疑 | **过度概括**：只有其中一份副本路径有误，另一份是正确的 |
| 某文档存在性未核 | 复核后确认**存在** |

另有整改过程中的 2 次自身失误（路径解析器一度越出仓库边界、把一条链接改向不存在的文件）——均在 dry-run 或校验环节被拦下，未污染仓库，过程留痕。

**为什么把这些写出来**：一个只展示正确结论的审计记录没有价值，因为无法判断它是否真的执行过。

## 可迁移的部分

1. **自举先于结论**：先建全量索引与唯一对账基准，再允许任何数量结论出口。
2. **同一模型下靠信息可见性制造不对称**：让取证者拿不到预期答案，结论才不会被牵引。
3. **区分"未核实"与"不存在"**：覆盖边界（不可读区域、深度限制、红线约束）必须显式声明，不能静默略过。
4. **预置基线必须独立复核**：本次对预先交底的事实逐条复核，结果有 1 条被证伪、2 条需纠正、1 条需补口径——**直接采信就会写错三处**。
5. **模板复现 ≠ 污染**：判断"内容污染"前先看层级与代码围栏上下文。
6. **同义不同层的矛盾并列而非择一**：如"转折点是 ADR-005/006"与"最关键转折点是 ADR-007"分属机制实现层与静态资产层，强行统一会制造新错误。
